# CAN-шина BMW E90 и данные KSW: база знаний

Справочник для агента `can-engineer-e90` (`.claude/agents/can-engineer-e90.md`) и для всех, кто чинит данные автомобиля в E90 OS.

Обозначения достоверности:
- **[машина]** — проверено на нашей машине (E90 + магнитола KSW);
- **[DBC]** — есть в открытом DBC, на нашей машине не проверялось;
- **[гипотеза]** — встречается на форумах или выведено логически, нужно проверить.

## 1. Как данные доходят до лаунчера

```
ЭБУ (DME, DSC, KOMBI, IHKA, CAS, JBE…)
   │  PT-CAN 500 кбит/с ── шлюз JBE ──┐
   │                                   ▼
   └────────────── K-CAN 100 кбит/с ──► MCU магнитолы KSW (CAN-декодер в жгуте/квадлоке)
                                          │  UART
                                          ▼
                     Android: системный сервис "wits_pms"
                     (com.wits.pms.IPowerManagerAppService)
                                          │  getStatusString("mcuJson"), транзакция 9
                                          ▼
                     KswCar.read() → CarState  (app/.../CarData.kt)
```

- Лаунчер не видит CAN напрямую. Он читает только то, что MCU KSW уже разобрал и положил в JSON `mcuJson` → объект `carData`. **[машина]**
- Если поля нет в `carData`, его не прочитать из Android без root и без дополнительного железа, даже если сигнал есть на шине.
- В E90 шины: **PT-CAN** (500k, двигатель, DSC, АКПП), **K-CAN** (100k, кузов, комфорт, приборка, климат), **F-CAN** (шасси, датчики DSC), **MOST/опт.** (мультимедиа), **D-CAN** (диагностика OBD, 500k). Шлюз — **JBE (JBBF)**: часть сообщений PT-CAN (например 0x0AA, 0x1D0) дублируется на K-CAN. **[DBC]**
- MCU KSW для E90 почти наверняка подключён к **K-CAN** (100k) через жгут к квадлоку. **[гипотеза]** То, что скорость и обороты приходят, согласуется с этим: 0x1A0/0x0AA есть на K-CAN.

## 2. Поля `carData` в `mcuJson` и что за ними стоит

| Поле `carData` | `CarState` | Смысл | Вероятный источник на CAN | Статус |
|---|---|---|---|---|
| `speed` | `speed` | скорость, км/ч | 0x1A0 `VehicleSpeed` (×0.103) или 0x1A6 | **[машина]** работает |
| `engineTurnS` | `rpm` | обороты | 0x0AA `EngineSpeed` (×0.25) | **[машина]** работает |
| `airTemperature` | `outsideTemp` | наружная температура, °C | 0x2CA или 0x366 `ExternalTemp` | **[машина]** работает |
| `mileage` | `range` | **запас хода**, км (не пробег!) | 0x330 / 0x366 `RemainingRange` | **[машина]** работает |
| `oilWear` | `consumption` | средний расход, л/100 | 0x362 (KOMBI, бортовой компьютер) | не приходит |
| `oilSum` | `fuel` | топливо в баке | 0x330 (литры) или 0x349 (сырые датчики) | не приходит |
| `handbrake` | `handbrake` | ручник | 0x34F `Handbrake_pulled_up` | не приходит |
| ? | — | двери, багажник | 0x0E2/0x0E6/0x0EA/0x0EE/0x0F2, 0x2FC | имя поля неизвестно |
| ? | — | ремень безопасности | 0x2FA `OccupancySeatBeltContact` | имя поля неизвестно |
| ? | — | климат | 0x242 `ClimateFrontStatus`, 0x2E6/0x2EA | имя поля неизвестно |
| ? | — | одометр (общий пробег) | 0x330 байты 0–2 | имя поля неизвестно |
| ? | — | средняя скорость | 0x362 | имя поля неизвестно |

Важно: имена полей KSW — китайский «транслит». `oil…` здесь значит **топливо** (油 = «масло/топливо»), а не моторное масло. `mileage` у KSW — это запас хода.

**Первое действие при любом «поле не показывается»:** снять полный `mcuJson` с машины (см. §5) и посмотреть, есть ли ключ вообще и меняется ли значение. Без этого дампа любые правки `KswCar.read()` — угадывание.

## 3. Таблица сообщений E90 (K-CAN, если не указано иное)

Формат сигнала: `старт_бит|длина@порядок±` (`@1` — Intel/little-endian, `@0` — Motorola/big-endian), затем `(множитель, смещение)`. Физическое значение = `сырое × множитель + смещение`.

### Двигатель и движение
| ID | Имя | Сигналы | Источник |
|---|---|---|---|
| 0x0A8 | Torque/Brake (DME) | момент; `BrakePressed` 61\|1 | [DBC] |
| 0x0AA | AccPedal (DME) | `EngineSpeed` 32\|16@1+ (0.25,0) об/мин; педаль газа 16\|16 (0.04,0) % | [DBC], на машине работает через KSW |
| 0x0CE | WheelSpeeds (DSC) | 4 колеса, 16 бит, (0.0625,0) км/ч | [DBC] |
| 0x130 | TerminalStatus (CAS) | клеммы KL R/15/50, ключ | [DBC] |
| 0x1A0 | Speed (DSC) | `VehicleSpeed` 0\|12@1- (0.103,0) км/ч; ускорения, рыскание | [DBC] |
| 0x1A6 | DistanceRoute | пройденный путь (счётчик) | [DBC] |
| 0x1D0 | EngineData (DME) | `TEMP_ENG` 0\|8 (1,−48) °C — **температура ОЖ**; `TEMP_EOI` 8\|8 (1,−48) °C — масло; `AIP_ENG` 24\|8 (2,598) гПа; `IJV_FU` 32\|16 — расход впрыска (сырой счётчик) | [DBC] |
| 0x1D2 | TransmissionDataDisplay (EGS) | положение селектора, `GearAct` 12\|4 (1,−4) | [DBC] |
| 0x3B0 | Reverse gear | `ReverseGear` бит 6 | [DBC] |
| 0x3B4 | PowerBatteryVoltage (DME) | `BatteryVoltage` 0\|12@1+ (0.015,0) В | [DBC] |

## 4. Что есть на шине, но KSW не отдаёт

- **Температура ОЖ и масла** — 0x1D0 на K-CAN, **[DBC]**. Физически сигнал есть, но в `carData` KSW его нет (проверить дампом).
- **Напряжение бортсети** — 0x3B4, **[DBC]**. То же самое. Батарея Android-устройства — это **не** напряжение 12 В.
- Варианты получить такие данные:
  1. **OBD ELM327 (BT/Wi-Fi)** через D-CAN: ОЖ (PID 0x05), напряжение (AT RV), впуск (PID 0x0F), только чтение. Без вмешательства в жгут.
     Реализовано в `Obd.kt`: адаптер (Bluetooth SPP, Bluetooth LE через сервисы FFF0/FFE0/18F0 или Wi-Fi) выбирается в «Настройки → Автомобиль», опрос `ATRV`, `0105`, `010F` раз в 2 с, протокол `ATSP6` (ISO 15765-4, 11 бит, 500k) с откатом на `ATSP0`. Обмен с адаптером пишется в logcat с тегом `E90OBD`.
  2. **Свой пассивный CAN-сниффер** на K-CAN (ESP32 + трансивер SN65HVD230/TJA1050 в режиме *listen-only*, 100 кбит/с) → USB-serial или BT в магнитолу. Даёт любые сообщения из §3. Подключение только на приём, без передачи в шину.

## 5. Диагностика: как снять `mcuJson`

1. ADB к машине: `C:\Users\Edo\platform-tools\adb connect 192.168.0.22:5555` (VPN на ПК выключить, настройки ADB не менять).
2. Быстрый дамп без приложения (ответ — hex-parcel со строкой UTF-16):
   ```
   adb shell service call wits_pms 9 s16 mcuJson
   ```
   Interface token `service call` пишет сам. Если вывод нечитаем — использовать вариант 3.
3. Надёжнее: лаунчер сам пишет каждый новый `mcuJson` в logcat с тегом `E90CAN` (`KswCar.read()`, пока открыта Главная или «Авто»). Снять: `adb logcat -s E90CAN > dump.txt`.
4. Сценарий проверки, каждый шаг отдельной записью лога: зажигание (KL15) → двигатель → открыть/закрыть каждую дверь и багажник → ручник вверх/вниз → пристегнуть/отстегнуть ремень → климат: температура ±, вентилятор, A/C → проехать, чтобы обновились расход и средняя скорость.
5. Сравнить ключи до/после каждого действия. Ключ, который меняется синхронно с действием, — нужное поле.

Типичные причины пустых полей:
- ключ называется иначе, чем ожидает `KswCar.read()` (самая частая) → исправить имя;
- значение приходит, но лаунчер его отбрасывает (`takeIf { it > 0 }`, единицы ×10, `0xFF` как «нет данных»);
- в заводских настройках KSW выбран не тот **CAN-протокол/модель** (E90 vs E60/F-серия, CIC/NBT/CCC), и MCU не разбирает часть сообщений. Менять это только вручную пользователем, после записи текущего значения;
- MCU вообще не декодирует этот сигнал для E90 → только §4.
